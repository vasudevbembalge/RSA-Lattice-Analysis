What is happening?

The primary cryptographic demonstration is lattice-based public-key encryption. Use the three buttons above in order:

  1. GENERATE LWE KEY PAIR produces Public Key (A, b), built from public parameters (A, q), secret key s, and error e as b = A s + e (mod q).
  2. ENCRYPT WITH PUBLIC KEY takes the plaintext m and public key (A, b) with fresh randomness r and encryption noise and produces the LWE ciphertext (u, v). Step 2 uses (A, b) only.
  3. DECRYPT WITH SECRET KEY takes the ciphertext (u, v) and secret key s and recovers the message. Step 3 uses s only.
  4. The recovered message is then compared with the original plaintext.
  5. Afterwards, the LATTICE REPRESENTATION gives the lattice interpretation of those noisy modular relations, and LLL is shown separately as lattice basis reduction.

The two equations above are the ones implemented in `educational_lwe.py`: one LWE sample per message symbol, with u = Aᵀr + e₁ (mod q) and v = bᵀr + floor(q/p) · symbol + e₂ (mod q), where floor(q/p) · symbol is the message embedding. About / Research Methodology

Academic specifications, algorithmic foundations, and system boundaries

Project Problem Statement

Public-key cryptography is widely used for secure communication, while lattice-based computational techniques provide important tools for studying the mathematical structure of cryptographic problems. There is a need for an educational software framework that demonstrates RSA cryptographic operations together with lattice representation and LLL reduction in an interactive and measurable environment.

Mathematical Methodology

RSA Cryptographic Workflow

Uses standard asymmetric pairs with $e = 65537$. Encryption incorporates optimal asymmetric encryption padding (RSA-OAEP) with SHA-256 and MGF1 to prevent chosen-ciphertext attacks, strictly avoiding textbook RSA.

LLL Lattice Basis Reduction

Given basis vectors $\mathbf{b}_1, \dots, \mathbf{b}_n \in \mathbb{Z}^m$, computes Gram-Schmidt vectors $\mathbf{b}_i^* = \mathbf{b}_i - \sum_{j=1}^{i-1} \mu_{i,j} \mathbf{b}_j^*$. Implements size reduction ($|\mu_{i,j}| \le 0.5$) and the Lovász condition $\|\mathbf{b}_k^*\|^2 \ge (\delta - \mu_{k,k-1}^2)\|\mathbf{b}_{k-1}^*\|^2$.

Scope & Academic Limitations

  • Strict Scope: LLL reduction is demonstrated as a lattice-analysis technique. Private-key recovery is strictly outside the scope of this implementation.
  • Numerical Limits: The C LLL engine accepts integer basis entries up to $|b_{i,j}| \le 2^{31}-1$ to guarantee absence of silent 64-bit integer register overflow during dot product calculations.
  • Future Work: Arbitrary precision LLL (GMP/MPFR), BKZ reduction, and post-quantum lattice cryptography (ML-KEM / Dilithium).
